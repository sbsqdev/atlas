# Rehab Academy

Образовательная платформа по реабилитации и восстановлению на русском языке (интерфейс также частично на казахском и английском).

**В первую очередь — для спортсменов: бегунов, марафонцев, любителей.** Спортсмен видит упрощённое приложение: главная с курсом, «Мои курсы», 3D-атлас тела, прогресс и сертификаты. Курсы для специалистов, симуляции, виртуальные пациенты, группы и тарифы ему не показываются.

**Следующий этап — специалисты** (реабилитологи, тренеры, спортивные врачи, вузы и клиники). Для них уже работают: 3D-лаборатория анатомии, пошаговые симуляции, виртуальные пациенты, курсы (LMS), тестирование, учебные группы, аналитика и подписки. На публичной странице этот раздел отмечен как «Скоро · для специалистов».

Аудитория задаётся у пользователя (`User.track`: `athlete` или `pro`) и у курса (`Course.audience`). Спортсмен видит только курсы, где указан `athlete`. Новый курс в конструкторе по умолчанию создаётся для спортсменов.

> **Только для образовательных целей.** Платформа не ставит диагнозы, не даёт рекомендаций по лечению и не заменяет решение лечащего специалиста. Весь учебный контент помечен как требующий проверки медицинским экспертом (`verified: false`).

## Режимы данных

| Режим | Где хранится | Что обеспечивает доступ |
|---|---|---|
| **Демо (по умолчанию, текущая сборка)** | `localStorage` браузера (`ra-db`, `ra-session`) | RBAC и изоляция организаций в `src/data/api.ts` + `src/data/rbac.ts`. Это проверки на стороне клиента, только для UX. |
| **Продакшен (Supabase/PostgreSQL)** | `supabase/migrations/0001_init.sql` | Политики Row Level Security, триггеры, серверная проверка тестов (`grade_attempt`) и выдача сертификатов (`issue_certificate`). |

В демо-режиме пароли хешируются через PBKDF2-SHA-256 (100 000 итераций, WebCrypto). Демо-режим не подходит для реальных персональных данных. Для пилота с реальными пользователями нужен Supabase-адаптер (см. «Дальнейшая работа»).

Каждая коллекция в `src/data/db.ts` соответствует одной таблице в SQL-схеме. Интерфейс обращается к данным только через `src/data/api.ts`, поэтому адаптер заменяется в одном месте.

## База данных (Supabase)

```bash
# 1. Создайте проект Supabase, затем примените схему:
psql "$DATABASE_URL" -f supabase/migrations/0001_init.sql
# 2. Только для стенда/демо (создаёт демо-аккаунты с паролем demo1234!):
npm run gen:seed     # пересобирает supabase/seed.sql из src/data/content/*.ts
psql "$DATABASE_URL" -f supabase/seed.sql
```

В схеме есть: organizations, profiles (связаны с `auth.users`), courses, course_modules, lessons, anatomy_structures, simulations, virtual_patients, assessments, questions, enrollments, lesson_progress, assessment_attempts, simulation_attempts, patient_attempts, anatomy_views, activity_log, classes, class_students, assignments, feedback, certificates, plans, subscriptions, content_reviews, audit_logs, notifications.

Ключевые правила на сервере:
- Каталог: только `published` курсы платформы или своей организации, только для вошедших пользователей. Авторы видят свои черновики.
- Ключи ответов (`questions`) студентам недоступны. Результат теста считает функция `grade_attempt()`, поэтому подделать балл с клиента нельзя.
- Пользователь не может сам сменить роль или организацию (триггер `guard_profile_update`).
- Переходы `medical_review → approved → published` выполняет только проверяющий (триггер `guard_course_status`).
- Данные одной организации не видны другой. Оплата не симулируется: `check (source <> 'payment' or status <> 'active')`.

Проверка RLS на локальном PostgreSQL 15+ (в этой сессии все проверки прошли на PostgreSQL 16):

```bash
PGHOST=/var/run/postgresql PGUSER=postgres npm run test:rls
```

## Запуск на fab3d-scan.com

Сайт FAB3D Academy открывается в корне `https://fab3d-scan.com`. Старые ссылки `/academy/...` перенаправляются в корень, Human Atlas переехал на `/atlas/`.

### Что видит посетитель
Публичная страница на русском и казахском (переключатель RU / KZ): три курса, «что внутри», регионы Казахстана, эксперты, тарифы, «как начать», отзывы, вопросы, контакты. Кнопка «Смотреть демо» открывает платформу от имени демо-бегуна: первый модуль каждого курса и 3D-атлас доступны бесплатно, остальные уроки и тесты — за пэйволлом.

### Как человек получает доступ
1. **Заявка.** Форма на сайте (имя, email, WhatsApp/Telegram, город, вид спорта, тариф) приходит на `CONTACTS.formsEmail` через FormSubmit.
2. **Оплата** по ссылке Kaspi (`KASPI_URL`), в комментарии — email.
3. **Код доступа.** Владелец открывает `https://fab3d-scan.com/issue`, один раз импортирует файл приватного ключа `fab3d-access-private-key.json` (он хранится только в браузере владельца и **не лежит в репозитории**), вводит email и тариф, нажимает «Создать код» и «Открыть письмо». В письме — ссылка `…/activate?email=…&code=…`: человек открывает её, и доступ открыт на 31 день (персональное сопровождение — 92 дня). Журнал выданных доступов можно скачать в CSV.
4. **Продление:** после следующей оплаты выдайте новый код на тот же email.

Код подписан ключом ECDSA P-256 (`src/data/access.ts`), подделать его без приватного ключа нельзя. Ограничение статического сайта: прогресс хранится в браузере, на новом устройстве человек снова открывает ссылку из письма. Ссылки YouTube видны в коде сайта, поэтому видео лучше публиковать с доступом «по ссылке».

**FormSubmit:** после первой отправки любой формы на почту придёт письмо «Activate form» — подтвердите его, иначе заявки не будут доставляться.

### Где что настраивается
- `src/data/content/launch.ts`:
  - `CONTACTS` — WhatsApp, Telegram, Telegram-канал, почта для форм;
  - `KASPI_URL`;
  - `PRICING` — первый поток 20 000 ₸ за первый месяц для первых 500, подписка 10 000 ₸ в месяц, персональное сопровождение 200 000 ₸;
  - `LEGAL` — продавец «SB dev», **БИН/ИИН и адрес нужно заполнить до приёма платежей**;
  - `REVIEWS` — только реальные отзывы;
  - `REGIONS` — 20 городов, в поле `chat` вписывается ссылка на Telegram-чат города.
- Ссылки на видео: `RUN_LINKS` (`content/runners.ts`), `TRI_LINKS` (`content/triathlon.ts`), `KZ_LINKS` (`content/kazakhstan.ts`).
- Оферта и политика конфиденциальности: `src/pages/Legal.tsx` (страницы `/offer` и `/privacy`). Тексты — черновик для запуска, их нужно проверить у юриста.

### Курсы
- «Колени, стопы и восстановление: курс для бегунов» — `content/runners.ts`.
- «Триатлон без травм» — `content/triathlon.ts`, гипотезы о потребностях триатлонистов — `docs/custdev-triathlon.md` (модельный кастдев, не реальный опрос).
- «Бег в Казахстане: климат, регионы и сезон» — `content/kazakhstan.ts`: мороз и гололёд, беговая дорожка, жара и тепловой удар, горы Алматы, смог, тренировки в Рамазан, сезон стартов.

Курсы обновляются из кода при каждом запуске. Интерфейс переведён на казахский; уроки пока на русском. Казахский текст нужно вычитать носителю языка.

### Сообщество, профиль и нетворкинг
- **«Мой профиль»:** фото (сжимается до 480 px и хранится на устройстве), город, виды спорта, цель, ближайший старт, личные рекорды, «о себе», Instagram, Telegram, Strava, отметка «открыт(а) к знакомствам».
- **Карточка спортсмена:** ссылка вида `/a/…`, в которую упакован профиль без фото и email. Её можно отправить в чат города или поставить в описание профиля. Сервер не нужен.
- **Каталог участников** в «Сообществе». Человек отправляет карточку через форму, вы проверяете и добавляете её в `MEMBERS` в `launch.ts`. Публикуются только те, кто дал согласие.
- **Сообщество:** чаты городов по климатическим зонам, уроки по зоне, формы «Хочу в чат города», отзыв и вопрос.

### Упражнения в 3D
Раздел «Упражнения 3D» и блок под уроками с программами упражнений (колени — `l-r6`, икры и стопа — `l-r10`, `l-t15`, плечо — `l-t7`, силовая — `l-t17`). Каждое упражнение показывает 3D-человечек: пауза, замедление ×0,5, виды «3/4», «сбоку», «спереди», вращение мышкой или пальцем, счётчик повторов. Работающие мышцы подсвечены бирюзовым. Есть стул, платформа, стена и резина. Упражнения описаны ключевыми позами (углы суставов) в `src/features/exercises/library.ts`: новое упражнение — это ещё один набор поз. В пробном доступе открыты три упражнения (`free: true`).

### Сторис
Страница «Сторис» рисует картинку 1080×1920 по одному из трёх шаблонов: профиль спортсмена, старт или тренировка (дистанция, время и темп считаются сами), прогресс курса. Есть три цвета. Кнопка «Поделиться» на телефоне открывает системное меню (Instagram, Telegram, WhatsApp), на компьютере картинка скачивается.

### Консультации реабилитолога (MedLife, Алматы)
Страница «Консультация» и блоки-приглашения: на главной спортсмена, в каждом уроке курсов для спортсменов, в профиле, в сообществе и на публичной странице. Формат — онлайн или очно в центре. Заявка приходит на почту. Адрес центра и ссылку на карту впишите в `CLINIC` в `launch.ts`.

### Формы
Если форма не отправилась (например, FormSubmit ещё не активирован), человек видит кнопку «Отправить в WhatsApp» с уже заполненным текстом заявки, так что заявка не теряется.

### Полный доступ для владельца
На `/issue` (после импорта ключа) кнопка «Войти с полным доступом» открывает все уроки на этом устройстве на год, чтобы смотреть контент и показывать платформу.

Для суперадмина: одобрение, публикация, активация пилота и журнал аудита. Для администратора клиники: создание сотрудника с временным паролем. Также проверяются самостоятельная регистрация с ограничением по тарифу, изоляция курсов организации, мобильная вёрстка 390 px и отсутствие ошибок в консоли.

## Что реализовано

- **Аутентификация** по email и паролю, регистрация спортсмена, специалиста или преподавателя с согласием на обработку данных. Администраторов создаёт платформа (или администратор организации, с временным паролем).
- **5 ролей и RBAC** (`src/data/rbac.ts`) с изоляцией организаций. Ролевые дашборды строятся из сохранённых данных (Recharts).
- **3D-анатомия** (React Three Fiber, `public/models/knee.glb` и `foot.glb`): 18 структур коленной области и 24 структуры стопы и голеностопа из BodyParts3D, переключение регионов. Есть список и поиск, переключение систем, скрытие и изоляция, прозрачность, автовращение, зум, сброс, полный экран, инфопанель с источниками и анатомический квиз.
- **Движок симуляций**, управляемый данными (`src/data/content/simulations.ts`): введение → исследование на 3D-модели → решения → обратная связь → оценка → сохранение. Полностью готов сценарий «Анатомия коленного сустава и функциональное движение» (7 шагов, схема движения, множественный выбор, разбор ошибок, цели, литература). Ещё 6 сценариев в других категориях помечены «Скоро».
- **Виртуальный пациент**: синтетический случай передней боли в колене с анамнезом, запросом обследований, анализом и разбором. Без генеративного ИИ и без «диагнозов».
- **LMS**: курс → модули → уроки (текст, видео, 3D, симуляция, тест, файл), запись на курс, автосохранение места остановки, автозавершение уроков-симуляций и уроков-тестов, сертификат с кодом проверки и печатью в PDF.
- **Конструктор курсов** с жизненным циклом Черновик → Медицинская проверка → Одобрено → Опубликовано → Архив, историей проверок и комментариями проверяющего. В каталог попадают только опубликованные курсы.
- **Тесты**: 6 типов вопросов (один ответ, несколько ответов, сопоставление, последовательность, определение структуры на 3D-модели, клинический случай), проходной балл, лимит попыток, таймер с автозавершением, перемешивание вопросов и вариантов, три режима обратной связи.
- **Профиль компетенций**: теория (тесты), практическое мышление (симуляции и пациенты) и клиническая компетенция (не оценивается онлайн) показаны раздельно.
- **Учебные группы**: студенты, назначения со сроками, уведомления, результаты, отзывы, экспорт CSV. **Организация**: пользователи и места лицензии, потоки, назначение курсов сотрудникам, агрегированная аналитика.
- **Суперадмин**: организации, администраторы, ручная активация пилотных лицензий, заявки, пользователи, библиотека симуляций, журнал аудита, модерация контента.
- **Тарифы** в тенге (ориентировочные цены) и права доступа по тарифу. Заявка на пилот вместо оплаты: платежи не подключены и не симулируются.
- **Карьера**: превью с портфолио и **явным opt-in** видимости (по умолчанию выключено).
- **Настройки**: язык (RU, KK частично, EN частично), экспорт своих данных в JSON, сброс демо-данных.
